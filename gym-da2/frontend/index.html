3. Database Trigger

TRG_EQUIPMENT_MAINT_STATUS

AFTER INSERT ON MAINTENANCE: Automatically flips equipment STATUS to 'Maintenance'.

CREATE OR REPLACE TRIGGER TRG_EQUIPMENT_MAINT_STATUS
AFTER INSERT ON MAINTENANCE
FOR EACH ROW
BEGIN
    UPDATE EQUIPMENT
    SET STATUS = 'Maintenance'
    WHERE EQUIPMENT_ID = :NEW.EQUIPMENT_ID;
END;

DA-2 Project Evaluation Report

Generated on October 2024 · Individual Submission

FITCORE GYM MANAGEMENT SYSTEM

COURSE: DATABASE MANAGEMENT SYSTEMS · DIGITAL ASSIGNMENT 2

1. Problem Statement & System Scope

The FitCore Gym Management System is a database-driven platform engineered to streamline gym center operations. It manages members, certified personal trainers, exercise machinery, supervised equipment usage logs, machinery servicing/maintenance, and membership payment transactions. The system enforces relational integrity across all tables and eliminates data anomalies through BCNF normalization.

2. Relational Schema & Cardinalities (Matching DA1)

  • MEMBER (Member_ID, Member_Name, Age, Gender, Phone, Membership_Type, Join_Date)
  • TRAINER (Trainer_ID, Trainer_Name, Phone, Specialization, Experience)
  • EQUIPMENT (Equipment_ID, Equipment_Name, Category, Brand, Purchase_Date, Condition, Status)
  • EQUIPMENT_USAGE (Usage_ID, Member_ID, Equipment_ID, Trainer_ID, Usage_Date, Duration)
  • MAINTENANCE (Maintenance_ID, Equipment_ID, Maintenance_Date, Technician_Name, Cost, Remarks)
  • PAYMENT (Payment_ID, Member_ID, Amount, Payment_Date, Payment_Mode, Status)
Cardinalities: Equipment → Maintenance (1:M) · Member → Equipment_Usage (1:M) · Equipment → Equipment_Usage (1:M) · Trainer → Equipment_Usage (1:M) · Member → Payment (1:N)

3. Normalization Verification (1NF to BCNF)

1NF: All attributes contain atomic, indivisible values. No multi-valued or repeating groups exist.

2NF: Relations are in 1NF and every non-prime attribute is fully functionally dependent on the entire primary key. Because all entity tables have single-attribute primary keys, partial dependency is impossible.

3NF: Relations are in 2NF with no transitive dependencies (X → Y → Z). Decomposed usage, maintenance, and payment relations eliminate redundant entity attributes.

BCNF: For every functional dependency X → Y, determinant X is a candidate key. Hence all decomposed relations strictly satisfy Boyce-Codd Normal Form.

4. Summary of 10 Required Queries Implemented

  1. Multi-Table JOIN (4 Tables): Audit of usage sessions with Member, Equipment, and Trainer details.
  2. GROUP BY & HAVING: Identifies equipment categories with total maintenance exceeding ₹2,000.
  3. Correlated Subquery with NOT EXISTS: Finds inactive members with zero equipment workouts.
  4. Conditional Aggregation & CASE: Revenue collected vs pending dues grouped by membership tier.
  5. Subquery with AVG Comparison: Maintenance repair incidents costing above the gym facility average.
  6. Trainer Workload Analysis: Aggregates sessions supervised and unique client reach per coach.
  7. Financial Defaulters Report: Pulls pending member dues with phone contacts for recovery.
  8. Asset Health & Lifecycle ROI: Cumulative repair expense tracked against current machine condition.
  9. UNION Set Operation: Master directory consolidating member and trainer contacts into a single roster.
  10. Analytical Window Function (DENSE_RANK): Ranks machines by workout popularity within category.

5. PL/SQL Implementation Summary

Includes stored procedure SP_REGISTER_MEMBER with validation and DUP_VAL_ON_INDEX error handling, stored function FN_GET_MEMBER_TOTAL_PAID, database trigger TRG_EQUIPMENT_MAINT_STATUS, and explicit cursor CUR_TRAINER_WORKLOAD.
